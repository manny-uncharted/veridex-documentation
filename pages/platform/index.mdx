# Developer Platform

The Veridex Developer Platform is a single workspace with two operating modes that serve different personas.

## Build Mode — For Developers

Build mode optimizes for the developer's primary workflow: get an app registered, create bounded sessions, execute governed actions, and inspect results.

**Navigation:**
- **Overview** — App health, recent activity, quick actions
- **API Keys** — Key management, rotation, integration snippets
- **Session Studio** — App sessions, agent sessions, multi-session inventory
- **Agents** — Agent registry, labels, session provisioning
- **Activity** — Event stream with filters

[Learn more about Build mode →](/platform/build)

## Operate Mode — For Operators

Operate mode serves treasury leads, risk leads, and security teams who need to control, monitor, and audit autonomous execution.

**Navigation:**
- **Operations Overview** — Spend posture, pending approvals, incidents, session health
- **Approval Inbox** — Queue, detail view, approve, reject
- **Policies** — Limits, chains, recipients, approval thresholds
- **Incidents** — Severity, affected agent, related session, timeline
- **Traces** — Step-by-step execution history, reasoning, verdicts
- **Evidence Export** — JSON and CSV audit bundles

[Learn more about Operate mode →](/platform/operate)

## Shared Workspace Model

Both modes share the same underlying data:
- One identity system (passkey-based)
- One activity feed
- Shared session, approval, incident, and trace models
- Users land in Build by default; operators switch to Operate from the workspace nav
